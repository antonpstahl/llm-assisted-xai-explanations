# analyses/

Scripts and reports that recompute and check the numbers in the paper from `results/`. Nothing here calls an LLM API, so everything runs offline.

## Which numbers are in the paper

The paper reports **run 2**. Run 1 was the first complete run. Before the paper was finalized, two problems were found and fixed. The scratchpad filter only removed `<analysis>` blocks, so `<thinking>` blocks reached the scored answers, and the XGBoost plots carried no title with the feature importance. Run 2 re-stripped all stored answers and regenerated every record that had seen an untitled XGBoost plot. The rules for interpreting run 2 were written and committed before its numbers were known (`run2_decision_rules.md`). Run 1 is kept as an audit trail. Its numbers are superseded.

| Path | What it is |
| --- | --- |
| `ledger_run2/` | Numbers ledger of run 2. **These are the numbers in the paper.** `mc24.json` and `mc18.json` hold the two Monte Carlo variants of Section 5.4 and Appendix F. |
| `ledger_run1/` | The same ledger for run 1, before the two fixes. Kept for comparison only. |
| `run2_decision_rules.md` | Interpretation rules for run 2, written before the run-2 numbers were known. |
| `numbers_ledger.py` | Recomputes the evaluation numbers of Sections 5.3 to 5.7 from `results/` into one JSON file. `--diff` compares two ledgers key by key. |
| `monte_carlo_orderings.py` | The two Monte Carlo variants of Section 5.4 and Appendix F (`--variant 24`, `--variant 18`). |
| `gt_verification.md`, `generate_gt_verification.py` | Ground-truth verification and threshold sensitivity (Section 5.2). |
| `error_examples_by_formtype.md`, `generate_error_examples.py` | Qualitative error analysis by form type (Section 5.8). |
| `restrip_scratchpad.py` | One-off fix applied between the runs: strips leaked scratchpad blocks from stored answers. |
| `invalidate_xgb_plot_consumers.py` | One-off step applied between the runs: deletes the records that saw the untitled XGBoost plots, so they could be regenerated. |

The two `.md` reports are regenerated by their scripts, and `tests/test_analyses_consistency.py` fails if either is stale.

## Usage

```bash
python analyses/numbers_ledger.py --out ledger.json
python analyses/numbers_ledger.py --diff analyses/ledger_run1/ledger.json analyses/ledger_run2/ledger.json
python analyses/monte_carlo_orderings.py --variant 24
```
